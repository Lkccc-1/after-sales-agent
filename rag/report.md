# RAG 检索对比实验（LlamaIndex 纯向量 vs Dify 混合检索）

- 日期：2026-11-10
- 环境：Windows 11 / Python 3.12 / `llama-index` + `BAAI/bge-small-zh-v1.5`（本地 CPU）
- 语料：`kb/` 15 篇售后政策 Markdown
- 题目：`rag/labels.csv` 12 条，标注期望文档 + 答案关键句
- 变量：分段 300 / 500 / 800 字（overlap 10%）× TopK 3 / 5，共 6 组
- 原始数据：`rag/result.json`（每组含逐题 rank 与命中片段文件名）

## 指标定义

| 指标 | 含义 |
|---|---|
| doc_recall | 期望文档是否出现在 top-k 片段里 |
| top1_doc | 第 1 条召回片段是否来自期望文档 |
| mrr | 期望文档首次出现的排名倒数（1/rank） |
| clause_recall | top-k 中是否有「来自期望文档且包含答案关键句」的片段 |

> 只看 doc_recall 会看到 6 组全是 1.0，因为没有区分度——这本身就是结论：**文档级召回对小语料太粗，必须看片段级**。

## 结果

| chunk | top_k | doc_recall | top1_doc | MRR | clause_recall |
|---|---|---|---|---|---|
| 300 | 3 | 1.0 | 0.917 | 0.958 | 1.0 |
| 300 | 5 | 1.0 | 0.917 | 0.958 | 1.0 |
| 500 | 3 | 1.0 | 1.0 | 1.0 | **0.917** |
| 500 | 5 | 1.0 | 1.0 | 1.0 | 1.0 |
| 800 | 3 | 1.0 | 1.0 | 1.0 | 1.0 |
| 800 | 5 | 1.0 | 1.0 | 1.0 | 1.0 |

## 三个问题

### 1. 哪种分段 + TopK 组合召回最好？

**800/3、800/5、500/5 三组并列满分**。若只选一组：**500/5**——它在四个指标上全满，且片段比 800 小，塞进上下文的成本更低。

### 2. 和 Dify 内置混合检索差多少？

**不能直接对比，只能说各自的结果。**

- Dify `06_评测/评测报告.md` 记录：11 条政策类用例的**引用正确率 11/11**（混合检索 + 路由 + query 模板），但 E19「运输中拒收」仍出现检索未召回。
- 本实验：12 条题纯向量 `doc_recall 12/12`，`clause_recall` 最好 12/12、最差 11/12。
- 口径差异有三处：题目集合不同（11 vs 12，本实验含 E19 同类拒收题）、Dify 是「语义 + 关键词」混合且带路由，本实验是纯向量、无 rerank、无 query 改写。**所以不能说「LlamaIndex 追平或超过 Dify」**，只能说：在这个小语料上，纯向量已足够召回，Dify 的混合检索优势在当前题集里没有可测出的增量。

### 3. 差在哪？——具体到失败题目

唯一有差异的是「**过保了还能免费维修吗？**」（期望 13-数码3C激活与保修政策）：

- **chunk=300**：Top-1 被 `11-大件家电与安装类商品政策.md` 抢走，期望文档掉到第 2。原因是 300 字把 13 号文档的保修条款切得太碎，单片段语义信号弱；11 号文档里「保修」字样形成了干扰。
- **chunk=500 + top_k=3**：文档排名第 1，但 `clause_recall` 失败——召回的 500 字片段里没有「保修期」条款，条款被切到了下一个片段。**这正是分段切断条款的实证**，与 Dify 评测里 E05「生鲜 24 小时时限与赔付比例被切在不同段」是同一类问题。
- **chunk=500 + top_k=5**：多召回 2 个片段后补回该条款，四项指标全满。

结论：**分段大小不是越大越好，而是「条款完整度」和「上下文成本」的权衡**。500 字 + TopK 5 在这个语料上是稳的；如果只用 TopK 3，建议把 500 提到 800，或者对长条款做父子分段（父段给上下文、子段做检索）。

## 局限

- 12 条题、15 篇文档，小样本；doc_recall 已到天花板，结论主要来自 top1 / MRR / clause_recall。
- 只测了 `bge-small-zh-v1.5`，没测 bge-large / 其他 embedding，也没加 rerank。
- 关键句是我人工标注的，判分靠字符串包含，偏宽松；换措辞的答案可能漏判。
- Dify 的 11/11 是引用正确率，本实验是检索命中率，两者不是同一指标，报告里不要混写。

## 复现

```bash
python rag/compare.py    # 首次会下载 bge-small-zh-v1.5（约 100MB）
```

Windows 上 LlamaIndex 的模型缓存落在 `C:\Users\<user>\AppData\Local\llama_index\llama_index\Cache`；本机因不支持符号链接会多占一些空间，属正常警告。
